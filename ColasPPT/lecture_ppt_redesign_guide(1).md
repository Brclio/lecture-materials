### 1.2 大屏工程诊断：为什么投影和 2K/4K 屏上“显小、难看清”？

通过实测 CSS 与 1080p / 2K / 4K 渲染图，定位到 **6 类确定性工程硬伤**：

1. **致命的“居中孤岛”尺寸锁死（4K 屏下整页内容缩成中间不到 1/4 面积）**：
   - CSS 写死了 `:root { --u: min(1vw, 1.76vh, 16px); }` 和 `.frame { width: min(100%, 180vh, 1750px); }`。
   - 所有字号用 `clamp(min, calc(var(--u)*k), max)` 再次封顶（正文上限 24–28px，标签/图注上限 16–20px）。一上 2K/4K 大屏或礼堂巨幕，内容死死缩在中央，四周全是无效留白。
2. **大学礼堂后排视距（15–25 米）下的字号严重偏小**：
   - 阶梯教室/礼堂大屏的**最低可读字号红线**（按 1920×1080 基准画布）：主标题 **72–96px**、卡片标题 **34–44px**、正文 **≥ 28px**、图注/标签 **≥ 22px**。
   - 现有大量页面正文仅 `20–24px`，截图内文字、SVG 标签、步骤说明甚至只有 `11–18px`（如 P05 书页、P07 微信图、P13–14 简历图、P22 安装对比、P30 星型图 11px、P33 Google 窄带图）。
3. **二维码过小 & 同屏打架**：
   - P10（140px）、P20（130px）、P27（110px）、P49 右侧三码（126px）在礼堂中后排完全无法对焦扫码；P05/P31 只放了小按钮不直出码；P49 同屏塞 4 个码导致手机扫码互相串码。
   - **大屏标准**：需要现场扫码的二维码边长必须 **≥ 240px（1920 基准，约占屏高 22%–26%）**，单页最多放 **2 个码**，并保留“点击放大全屏扫码弹窗”作为兜底。
4. **`mix-blend-mode` 失效导致的“刺眼白框补丁”**：
   - **P12（600 份简历）** 整张底图在金色背景上出现一块巨大的纯白色矩形框；**P48（纸船）** 和 **P15（印刷机）** 也存在清晰可见的亮底矩形边界。根因是 `.slide.is-active` 的 CSS 动画与 `overflow: hidden` 创建了独立层叠上下文，隔离了 `mix-blend-mode: multiply`。
5. **6 处肉眼可见的排版/内容穿帮 Bug**：
   - **P10**：旧信封 `12345678@qq.com` 被新信封遮掉左半边，像排版出错。
   - **P17 / P22 / P31 / P43**：四页出现尴尬的**孤字换行**（“是逻/辑。”、“内存与显存合/一”、“没接触过 AI 的/人”、“知道不做什么。”的“么。”）。
   - **P27**：`iPhone（安 / 全·麻烦）` 生硬断词换行。
   - **P19**：B 站截图右上角直接露出了 **「0 播放 · 退回仅自见」** 的废稿视频；红框问号遮挡封面左上角。
   - **P31**：红色 `1` 徽章挡住 Google 标志露出半个 `le`。
   - **P33**：左侧 `01搜索` `02出版社` 编号与文字零间距粘连；豆包截图顶部半行字被腰斩且带草率红涂鸦线。
   - **P35**：左侧「眼前利益」全列用浅灰印在米色底上，投影仪强光下几乎隐身。
   - **P49**：右侧第二行直接写着草稿备注 **「交流群码预留位，先用视频号代替」**！
6. **视觉模板疲劳**：
   - 9 张蓝底章节页（Q0–Q8）完全一模一样，3 张黄底金句页完全一模一样，35 张米白底页面结构雷同，缺乏随情绪切换的视觉节奏。

> **用法**：将下面这段提示词连同你的 HTML 文件直接交给 AI（如 Codex / Claude Code / Antigravity），一次性完成底层架构的大屏化改造，然后再按第三部分分批精修每一页。

```markdown
你是资深的大学礼堂大屏演示文稿（HTML Slide Deck）架构师与视觉设计师。请对现有的单文件 HTML PPT 进行全局大屏化与视觉系统底层重构（先改造全局 CSS 架构、响应式缩放引擎、页眉页脚与公共组件，保留所有 49 页语义内容与弹窗/快捷键能力）：

【一、彻底解决大屏显示偏小与 2K/4K 缩成孤岛的问题】
1. 放弃 `--u: min(1vw, 1.76vh, 16px)` 和 `.frame { max-width: 1750px }` 的硬上限架构。
2. 改用「1920×1080 基准画布 + 视口等比缩放（Stage Scale Engine）」方案：
   - 桌面端/投影端：将 `.frame` 固定在逻辑尺寸 `1920px × 1080px`，由 JS 监听 `resize` 动态计算 `scale = Math.min(window.innerWidth / 1920, window.innerHeight / 1080)`，通过 `transform: scale(var(--stage-scale))` 完美居中铺满任意 1080p / 2K / 4K / 超宽屏，同时 `body` 背景色与当前页 `--page` 同步，绝不出现黑边或孤岛。
   - 保留移动端竖屏（`max-width: 768px`）的流式阅读布局及 `@media print` 导出 PDF 能力。
3. 建立「礼堂后排 20 米清晰可读」字号红线（基于 1920×1080 逻辑像素）：
   - 章节超大标题 / 金句：`80px–112px`
   - 页面主标题 `h2`：`64px–76px`（严禁孤字换行，配合 `text-wrap: balance` 与合理断行）
   - 卡片/分栏标题 `h3`：`36px–44px`
   - 核心正文：`28px–32px`（行高 1.5–1.6）
   - 辅助标注 / 图注 / 标签：`≥ 22px`（严禁出现小于 20px 的内容文字）
4. 压缩冗余壳层空间，把面积还给内容：
   - 顶部 `.mast` 高度收紧至 `72px`，底部 `.foot` 收紧至 `62px`，左右安全边距 `72px`。
   - 在封面页、全屏金句页、强视觉冲击页隐藏页眉分割横线，只保留轻盈的角落角标，释放画面呼吸感。

【二、修复全局视觉穿帮与大屏交互短板】
1. 消灭所有贴图白底框：凡是插画容器，不要依赖在动画/overflow 层下易失效的 `mix-blend-mode: multiply` 去隐藏不同色底图；为插画提供精准去背或同色底融合方案，并移除 `.slide.is-active` 造成层叠隔离的过渡写法（改用只对子元素或纯透明度短过渡且结束后释放，或直接简洁切换）。
2. 大屏扫码规范：
   - 页面内所有现场可扫二维码统一放大至至少 `220px–280px`（逻辑像素），配高对比白色静区边框 `12px`。

3. 对比度红线：所有文字与背景的对比度必须达到 WCAG AA 以上（≥ 4.5:1），彻底替换现有浅灰字（如 P35 左侧、P38 输入框占位字、P43 右侧标签框）。
```
